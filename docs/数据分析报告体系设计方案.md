# 换电业务数据分析报告体系设计方案

> 设计者：数据分析（报告）角色  
> 适用业务：共享电单车换电（citybike / sharing-citybike-pro）  
> 版本：v1.0　设计日期：2026-08-11  
> 数据基础：换电服务协议 23,213 份、签约用户近 30 天换电行为、违约/续租/服务单收入明细

---

## 一、为什么"报告不够深"——现状诊断

当前看板/报表主要停留在**罗列总量**阶段，难以支撑决策的根本原因有三：

| 深层问题 | 现状表现 | 后果 |
|---------|---------|------|
| **1. 只有总量，没有归因** | 例：含违约协议 6,188 份、累计违约支付 ¥2.38 亿，但不知道集中在哪些**城市/套餐/推广员/签约时段** | 看到风险，却**不知道该找谁、从哪里下手** |
| **2. 只有现状，没有趋势与分层** | 例：低频用户占比 20.8%、欠租 1,370 份，但**环比是升是降、哪些是刚掉队的新户、哪些是长期沉默老户**不清楚 | 无法区分"急性问题"与"慢性问题"，**资源平均撒** |
| **3. 看完不知道下一步** | 看板展示指标，但未绑定**决策动作与责任人** | 报告沦为"展示"，**不驱动经营动作** |

本方案的核心思路：**从"业务决策问题"倒推"要回答什么"，再倒推"需要哪些指标、维度和报告"**，让每一份报告都对应一个明确的经营动作。

---

## 二、设计原则

1. **决策导向**：每份报告必须回答一个经营问题，并给出"建议动作 + 责任方"。
2. **分层归因**：任何总量指标必须能下钻到「城市 → 网点 → 套餐 → 推广员/业务员 → 用户分层」。
3. **趋势 + 对比**：每个核心指标自带环比、同比、目标差，杜绝"单点数字"。
4. **风险前置**：把"事后统计"升级为"事前预警"（低频预警、欠租预警、违约预警）。
5. **口径唯一**：全公司共用一套指标定义与取数 SQL，避免"同一指标各部门数字打架"。

## 三、业务决策问题树（报告体系的源头）

```
经营目标：换电业务健康增长、风险可控、资产（押金/车辆）安全
│
├─ A. 用户健康度：用户在活跃吗？谁在流失？
│   ├─ A1 低频/沉默用户是谁、为什么掉队、怎么唤醒？
│   ├─ A2 新签用户首月活跃率是否达标？
│   └─ A3 用户生命周期价值（LTV）与流失预测
│
├─ B. 收入与续费：钱从哪来、会不会断？
│   ├─ B1 续租金额结构（套餐/城市/推广员）
│   ├─ B2 续费流失率与召回空间
│   └─ B3 服务单收入与毛利
│
├─ C. 风险与资产安全：哪些钱/车有危险？
│   ├─ C1 欠租催收优先级与人力分配
│   ├─ C2 违约集中人群与预警
│   └─ C3 押金/合约车资产回收风险
│
├─ D. 渠道与组织效能：人/网点效率高吗？
│   ├─ D1 推广员获客质量（签约量 vs 后续低频/违约率）
│   ├─ D2 网点产出与区域差异
│   └─ D3 业务员跟进动作转化率（回访→续费/回款）
│
└─ E. 城市/区域战略：资源往哪投？
    ├─ E1 各城市投入产出（协议数/收入/风险）
    └─ E2 新城市扩张 vs 存量城市深耕
```

> **关键转变**：报告不再按"数据有什么"组织，而是按"经营要决策什么"组织。

## 四、指标体系（分层 + 唯一口径）

### 4.1 指标分层

| 层级 | 定位 | 指标示例 |
|------|------|---------|
| **北极星** | 业务最终健康度 | 月活换电用户数、有效协议数（生效中且近30天有换电） |
| **经营层** | 规模/收入/风险 | 协议总数、续租金额、服务单收入、欠租金额、违约金额 |
| **效率层** | 人/渠道效能 | 推广员月均有效签约、网点单点产出、跟进转化率 |
| **预警层** | 前置风险信号 | 低频转化率、欠租新增率、新签首月沉默率 |

### 4.2 核心指标字典（首批，必须统一口径）

| 指标 | 定义 | 取数口径 | 预警阈值建议 |
|------|------|---------|------------|
| 有效协议数 | 状态=生效中 且 近30天换电≥1 | `status='working' AND lf30>=1` | 周环比 ↓>5% 预警 |
| 低频用户数 | 近30天换电≤2 单的签约用户 | 当前窗口计算 | 占比>25% 预警 |
| 低频占比 | 低频用户 / 活跃用户池 | — | 同上 |
| 欠租金额 | 状态=已欠租 的未缴租金合计 | `status='owe_rent'` 关联续租/租金表 | 新增>80单/周 预警 |
| 违约率 | 含违约协议数 / 协议总数 | — | >28% 预警 |
| 续租金额 | 已支付+成功 的续租订单金额 | `cb_user_exchange_rent_package_order` | 环比 ↓>10% 预警 |
| 新签首月活跃率 | 当月新签用户中首月换电≥4单占比 | — | <60% 预警 |
| 推广员有效签约 | 签约后30天仍活跃的用户数 | — | 人均<8 预警 |

> **治理动作**：以上口径写入《指标字典 v1》并冻结，任何报告/看板引用必须标注口径版本。

## 五、分析维度与用户分层模型

### 5.1 通用维度（所有报告可下钻）
- **地理**：城市（16个）→ 地区/区 → 签约网点
- **协议属性**：个人/企业、合约车/非合约、套餐类型、押金方式
- **时间**：日/周/月 + 签约 cohorts（按签约月分群看留存）
- **组织**：推广员 / 签约业务员 / 网点

### 5.2 用户分层模型（RFM 适配版）

针对换电业务，用 **R（最近换电）· F（换电频次）· M（贡献金额）** 给每个用户贴标签：

| 分层 | 定义 | 经营含义 | 对应动作 |
|------|------|---------|---------|
| 高价值活跃 | R近、F高、M高 | 核心收入来源 | 保活、会员权益 |
| 成长型 | R近、F中、M中 | 潜力用户 | 引导升套餐 |
| **低频预警** | R远或F≤2 | 流失前兆 | **唤醒活动+地推** |
| 沉默流失 | R>60天无换电 | 已流失 | 低成本召回/回收车辆 |
| 风险用户 | 欠租/高违约 | 资产风险 | **催收优先** |

> 当前看板已能识别"低频（F≤2）"和"欠租"，下一步需补 **R 维度（最近一次换电时间）** 才能做真正的流失预警。

## 六、报告矩阵（四类 + 专题）

> 频率与读者绑定，避免"一份报告人人看"。

### 6.1 日报（ operational ）
| 项 | 内容 |
|----|------|
| 读者 | 城市运营/客服组长 |
| 目的 | 当天异常与待办 |
| 核心 | 新增欠租清单、当日新转低频用户、催收跟进完成率 |
| 决策动作 | 当日派单：哪些欠租用户进入催收队列 |

### 6.2 周报（tactical）
| 项 | 内容 |
|----|------|
| 读者 | 区域经理 |
| 目的 | 一周健康度与归因 |
| 核心 | 有效协议环比、低频占比趋势、**欠租/违约按城市+推广员归因 Top10**、跟进转化率 |
| 决策动作 | 调整下周地推/催收人力分配；约谈高违约推广员 |

### 6.3 月报（strategic）
| 项 | 内容 |
|----|------|
| 读者 | 业务负责人/管理层 |
| 目的 | 经营结论与资源决策 |
| 核心 | 收入结构（续租/服务单）、城市投入产出排名、用户分层迁移、风险敞口、LTV 估算 |
| 决策动作 | 下月资源投放（扩城/深耕/收缩）、套餐定价、风控策略 |

### 6.4 专题报告（on-demand，以下为重点深入模块）

| 专题 | 回答的决策问题 | 深度分析方法 |
|------|--------------|------------|
| **低频用户洞察与挽回** | 谁在流失、为什么、花多少成本唤醒划算？ | 分群（新户沉默 vs 老户衰减）× 城市 × 套餐；测算唤醒 ROI（召回换电收入 vs 地推成本） |
| **欠租催收效能** | 先催谁、派多少人？ | 欠租金额×违约次数×押金 三维打分排序；按推广员/城市算催收回款率 |
| **违约风险预警** | 哪类用户最可能违约、能否提前拦截？ | 违约用户特征建模（首签套餐/地区/频次），输出高风险名单 |
| **续租收入结构** | 收入靠什么撑、哪里能提？ | 续租金额按套餐/城市/推广员拆解；续费流失漏斗 |
| **城市/网点效能** | 资源往哪投？ | 单城市协议数×收入×风险×获客成本 综合评分排名 |
| **推广员效能** | 谁带来的用户质量高？ | 推广员签约量 **vs** 后续低频率/违约率/续费率（质量而非数量） |

## 七、专题深度示例：低频用户洞察（展示"深入"长什么样）

不只是"低频占比 20.8%"，而是：

1. **分群归因**：低频用户中，新签<30天占 X%、老户衰减占 Y%、合约车占 Z% —— 三类问题解法不同。
2. **城市热力**：低频占比最高的 3 个城市（如宝安区 7,732 协议，需下钻其低频率）圈定为重点干预区。
3. **套餐关联**：低频用户集中使用哪类套餐？是否该套餐本身使用门槛高？
4. **唤醒 ROI**：对低频用户做 ¥X 补贴唤醒，预计召回 Y% 换电，增量收入 Z 元，ROI=Z/(成本) —— **直接给出"值不值得做"**。
5. **动作闭环**：清单 → 分配地推 → 跟进状态回写 → 下周报看低频占比是否下降（验证动作有效）。

> 这一步需要现有看板补充：**最近一次换电时间（R）、签约月份（cohort）、套餐维度低频率**——技术上已在库表（`cb_exchange_order.take_battery_time`、`rent_package_id`）可取。

## 八、数据治理与口径统一（根因解法）

"报告不够深"的底层往往是**数据没人管**。建议建立三条基线：

1. **指标字典（冻结版）**：所有指标定义+取数 SQL 入库评审，版本化管理（见 4.2）。
2. **取数单一来源**：报告/看板统一从 `sync.py` 抽数逻辑出数，禁止各部门各自写 SQL 导致口径分裂。
3. **决策动作回填**：看板"跟进/备注"字段即数据治理的一部分——把"看了报告后做了什么"沉淀为数据，下份报告才能评估动作有效性。

## 九、与现有看板的衔接（落地不推翻）

现有看板已具备：概览 KPI、低频分析、欠租催收、协议明细查询、一键同步、多人跟进。

| 现有能力 | 升级方向（纳入本报告体系） |
|---------|--------------------------|
| 概览 KPI | 补环比/同比/目标差 → 变成"月报经营概览"底表 |
| 低频分析 | 补 R 维度与分群 → 支撑"低频专题" |
| 欠租催收 | 催收清单直接作为"日报待办"数据源 |
| 协议明细查询 | 加"用户分层标签"列 → 支撑分群下钻 |
| 多人跟进 | 跟进转化率纳入"推广员/业务员效能"专题 |

## 十、落地路线图

| 阶段 | 周期 | 交付 | 解决 |
|------|------|------|------|
| **P0 口径统一** | 第1周 | 《指标字典 v1》+ 冻结取数逻辑 | 根因①：数字打架 |
| **P1 看板深化** | 第2-3周 | 补 R 维度、分群、环比；明细加分层标签 | 根因②：无趋势无分层 |
| **P2 报告产出** | 第4周起 | 周报/月报模板 + 低频/欠租/推广员 3 个专题 | 根因③：无决策动作 |
| **P3 预警自动化** | 第2月 | 低频/欠租/违约 预警名单自动推送日报 | 风险前置 |
